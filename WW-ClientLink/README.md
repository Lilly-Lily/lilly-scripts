# 명조 클라이언트 심볼릭 링크 도구 (WW-ClientLink)

명조(Wuthering Waves) 클라이언트 여러 개가 대용량 리소스 폴더를 공유하도록 심볼릭 링크로 연결해 주는 GUI 도구임. v1.1

공식(쿠로), 구글, 에픽, 스팀 등 클라이언트를 따로 설치하면 각각 100 GB 안팎을 차지함. 원본 한 곳에 실제 파일을 두고 나머지 클라이언트의 `Paks`, `UHD`/`HD`/`SD`, `Saved\Resources` 폴더를 원본으로 연결하면, 클라이언트마다 고유 파일(약 5 GB)만 남아 용량이 크게 줄어듦. 링크 생성뿐 아니라 업데이트 후 링크 클라이언트의 설정을 맞추는 [업데이트 후 동기화]까지 지원함.

> [!WARNING]
> 폴더를 실제로 이름 변경, 링크, 삭제하는 도구임. 사용 전 [면책 조항](#면책-조항)을 꼭 읽을 것.

## 다운로드

[Release 페이지](https://github.com/Lilly-Lily/lilly-scripts/releases?q=WW-ClientLink)에서 가장 최신 버전의 `WW-ClientLink-v버전.zip`(예: `WW-ClientLink-v1.1.zip`) 파일을 받을 수 있음. `Source code`는 저장소 전체 사본이므로 받지 말 것.

## 용어

- **클라이언트**: 런처(`launcher.exe`)와 게임 실행 파일(`Wuthering Waves.exe`)이 있는 설치 하나를 가리킴.
- **구성 파일**: 클라이언트 사이에 연결되는 폴더(`Paks`, `Saved\Resources`, UHD/HD/SD 리소스)를 가리킴. 링크 클라이언트는 구성 파일이 실제 폴더가 아니라 링크이므로 `구성 파일 없음 · 링크 연결됨`이 정상 상태임.

## 주요 기능

- **링크 생성**: 원본 클라이언트의 `Paks`, `Saved\Resources`(영상 포함), UHD/HD/SD 폴더를 대상 클라이언트에 심볼릭 링크로 연결함. [링크 실행]을 누르면 변경 내용을 팝업으로 확인한 뒤 진행하며, 대상의 기존 폴더는 삭제하지 않고 `_backup`을 붙여 보관함. 이후 대상 런처에서 [게임 복구]와 게임 실행을 확인하고, 확인 단계를 거쳐 [백업 삭제]로 정리함. 필요하면 [되돌리기]로 취소하며, 완료 후 링크 관리 목록에 등록할 수 있음.
- **클라이언트 이식 설정**: 런처(`launcher.exe`)만 설치되고 클라이언트가 없는 대상(빈 설치 폴더)을 고르면 설정 박스가 나타남. 런처 종류(공식/구글/에픽/스팀)와 품질(UHD/HD/SD)을 선택하면 원본 설정을 바탕으로 대상 런처의 설정 파일을 만들어 런처가 설치된 클라이언트로 인식하게 함. 실제 파일은 옮기지 않으며, 링크로 연결된 핵심 리소스 외의 나머지는 런처 [게임 복구]로 받음. 선택하면 원본의 DB 파일(`LocalStorage.db`, 게임 사용자 설정과 완료 임무 기록)도 함께 복사해 첫 실행 시 지난 임무 영상 리소스(약 29 GB)를 다시 받지 않게 함(기본 켬). 되돌리기를 지원하고, 완료 전에는 종류를 바꿀 수 있음.
- **링크 관리**: 클라이언트(원본 1 + 링크 3, 최대 4개)를 등록해 링크 현황 표로 확인하고, 연결, 해제, 깨진 링크 정리, 백업 삭제를 함. 링크 생성과 같은 안전 검사와 확인 팝업을 거침.
- **클라이언트 종류 구분**: 등록할 때 이름과 함께 런처 종류(공식/구글/에픽/스팀)를 정함. 런처 설정 파일로 종류를 자동 판정해 미리 선택해 줌(이식 설정의 종류 선택도 같음). 판정값은 도구 설정에 저장되며 등록 후 [수정]에서 바꿀 수 있음.
- **클라이언트 탐색**: 흔한 위치, Steam 라이브러리, 저장소 전체를 탐색(읽기만 함)함. 탐색 정확도는 빠름/보통/정확 중에서 고르고, 체크한 드라이브만 탐색함(세 단계 모두 적용, 하나도 체크하지 않으면 탐색하지 않음). 결과에는 런처, 클라이언트, 버전, 링크 대상 폴더 상태, 제안이 표시됨.
- **링크 해제**: 해제 후 복원 방식(백업 복원 / 원본에서 복사 / 비워두기)을 고름. UHD/HD/SD 폴더가 비게 되면 런처 설정에서 해당 품질 번들과 전용 팩 파일을 함께 정리하고, 삭제 내용은 확인 팝업에 먼저 보여 줌. `원본에서 복사`가 권장 항목이며 기본 선택됨(링크 해제 후 빈 파일·폴더를 원본 클라이언트로부터 채움). 복사를 고르면 해제 후 런처의 [게임 복구]로 무결성 검사를 하라는 안내가, 백업 복원을 고르면 백업이 구버전일 때 버전 표기와 리소스 버전이 어긋날 수 있다는 안내가 확인 팝업에 나옴(해제 후 [게임 복구]로 해결).
- **업데이트 후 동기화**: 원본을 업데이트한 뒤 링크 클라이언트의 설정 JSON 버전을 맞추고 사전 다운로드 파일을 안전하게 치워, 링크 런처에서 [게임 복구]만으로 끝나게 함.
- **상태 배지**: 클라이언트마다 `동기화`, `동기화 필요`, `최신`, `업데이트`, `링크 불가`, `미확인` 배지를 표시하고, `동기화 필요`(링크됨), `업데이트`·`링크 불가`(링크 안 됨)는 카드와 링크 현황 열을 붉은 배경으로 표시하고, 동기화가 필요하면 [동기화 순서 안내] 팝업으로 안내함. 열 머리의 [런처 실행]으로 해당 클라이언트의 런처를 바로 열 수 있음. 링크 관리 탭에 들어갈 때 `동기화 필요` 배지가 있으면 `업데이트 후 동기화 순서 안내` 창이, `업데이트` 배지가 있으면 `링크 연결 후 업데이트 순서 안내` 창이 각각 실행 1회당 한 번 자동으로 뜸(프로그램을 다시 실행하면 조건이 남아 있는 한 다시 뜸).
- **버전 검사**: 원본과 대상의 앞 두 자리 버전이 다르면 링크를 막고, 끝자리(패치 버전)만 다르면 링크는 허용하고 `패치 버전이 다르므로 업데이트 권장`으로 안내함. 클라이언트 파일은 있는데 `launcherDownloadConfig.json`에서 버전을 읽지 못하면(파일 없음, 손상, 버전 값 없음) `미확인` 배지와 원인을 표시하고 선택·등록을 막음(원본 탐색, 링크 탐색, 링크 관리 탐색 공통). 링크 탐색은 원본을 먼저 지정해야 대상을 고를 수 있음. 원본보다 낮은 클라이언트는 `업데이트 필요 · 런처 실행하여 업데이트`, 높은 클라이언트는 `링크 불가 · 원본보다 최신 버전`으로 안내함. 링크가 없는 클라이언트는 설정 파일 버전과 함께 `launcherDownload\common` 아래 버전 폴더(`3.8.0` 같은 이름) 중 `OriginResource.json`이 들어 있는 가장 높은 버전을 확인하고, 낮은 쪽을 기준으로 삼음. `OriginResource.json`은 그 버전이 설치될 때 남는 기록 파일이라 사전 다운로드만 받은 폴더에는 없고, 동기화가 사전 다운로드를 옮겨도 남아 있음. 링크 해제 때 백업을 복원해 설정만 최신이고 실제 설치는 옛 버전인 경우를 `업데이트`로 표시하기 위함임.

## 요구 사항

- Windows 10 이상, Windows PowerShell 5.1
- 관리자 권한 (심볼릭 링크 생성에 필요. 관리자가 아니면 실행할 때 UAC 창을 띄워 자동으로 다시 실행함)
- 원본과 대상 클라이언트가 모두 같은 PC의 로컬 드라이브에 있어야 함

## 사용법

1. [다운로드](#다운로드)한 zip의 압축을 풀고, `WW-ClientLink.ps1`과 `WW-ClientLink.bat` 우클릭 > 속성 > 하단 `차단 해제`를 체크함.
2. `WW-ClientLink.bat`을 더블클릭하고 UAC 창에서 [예]를 누름. (PowerShell에서 직접 실행하려면 `powershell -NoProfile -ExecutionPolicy Bypass -File .\WW-ClientLink.ps1`)
3. 모든 명조 런처와 게임을 종료함.
4. [링크 관리] 탭에서 `＋ 클라이언트 추가`로 원본과 링크 클라이언트를 등록함. 이름과 런처 종류를 정하고 원본/링크 대상을 선택함. 이미 등록된 클라이언트와 폴더가 서로 포함 관계이면 등록되지 않음.
5. 런처만 설치한 새 클라이언트는 [링크 생성] 탭에서 원본과 대상을 지정하면 나타나는 `클라이언트 이식 설정`에서 런처 종류를 고르고 [링크 실행]을 누름. 이후 대상 런처에서 [게임 복구]를 진행하고 ②를 확인함.
6. 연결할 칸을 선택하고 [링크 연결]을 누름. 이후 링크 클라이언트의 런처에서 실행과 [게임 복구]를 확인하고, 이상 없으면 [백업 삭제]로 정리함.

### 업데이트할 때

1. 원본 클라이언트만 일반 업데이트(사전 다운로드 포함)를 완료함. 링크 쪽 런처에서는 업데이트를 누르지 말 것.
2. 모든 런처와 게임을 종료하고, 도구의 [링크 관리] 탭에서 `동기화 필요` 배지를 확인함.
3. [업데이트 후 동기화]를 열고 ①을 실행함.
4. 링크 클라이언트마다 런처에서 일반 업데이트가 아닌 [게임 복구]를 하고, 클라이언트를 실행해 잔여 파일을 자동 업데이트함. 동기화 창의 ② 버튼을 처음 누르면 이번 동기화로 `backup_sync_*` 보관분이 생긴 링크 클라이언트의 런처를 모두 실행할지 한 번 묻고(탐색기를 거쳐 일반 권한으로 실행, [아니요]이면 다음 단계로 넘어가지 않음), 진행한 뒤 같은 버튼을 다시 눌러 확인함.
5. 모든 클라이언트의 실행이 확인되면 ②, ③으로 보관한 설정과 사전 다운로드 백업을 영구 삭제함.
6. 링크가 없는 클라이언트(`업데이트` 배지)는 동기화 대상이 아니므로 해당 런처에서 직접 업데이트함.

|---|---|
| `WW-ClientLink.ps1` | 도구 본체 |
| `WW-ClientLink.bat` | 본체를 콘솔 창 없이 실행하는 실행 파일 |
| `README.md` | 설명서 |
| `LICENSE` | MIT 라이선스 |
| `.gitignore`, `.gitattributes` | 저장소 설정 |

실행 중 도구 폴더에 `WW-ClientLink.json`(등록 정보)과 `logs`(로그)가 자동 생성되며 저장소에는 포함하지 않음.

## 동작 원리

1. 관리자 권한 확인: 관리자가 아니면 UAC를 요청해 자기 자신을 관리자 권한으로 다시 실행함. 심볼릭 링크 생성에 필요함.
2. 링크는 복사가 아니라 같은 폴더를 두 경로로 접근하게 만드는 것임. 어느 클라이언트에서 수정, 삭제해도 모두에 반영됨.
3. 링크 생성: 대상 폴더를 `_backup`으로 이름 변경 → 같은 자리에 심볼릭 링크 생성 → 경로 확인 → 실패하면 백업 복원. UHD/HD/SD를 연결할 때 대상 런처 설정에 없는 품질 번들이 있으면 원본 정보로 추가함.
4. 링크 클라이언트 런처로 업데이트(사전 다운로드 포함)하면 링크 너머 원본 파일이 패치 재료로 옮겨져 원본이 손상됨. 그래서 업데이트는 원본에서만 하고, 링크 쪽은 설정 JSON의 버전을 맞춘 뒤 [게임 복구]를 사용함.
5. [업데이트 후 동기화] ①: 링크 클라이언트의 `launcherDownloadConfig.json`, `launcherDownloadConfig\*.json`의 버전 필드를 원본 버전으로, `launcherDownload` 쪽 사전 다운로드 플래그를 `false`로 수정함. 파일 전체가 아닌 필드만 고치며, 임시 파일에 쓰고 검증한 뒤 교체함.
6. 사전 다운로드 파일(`launcherDownload` 합계 1 GB 이상일 때 감지, 100 MB 이상인 버전 폴더)은 `<Game>\backup_sync_<시각>\predownload`로 옮김. 중간에 실패하면 옮긴 파일을 되돌림. 수정 전 설정은 `backup_sync_<시각>\settings`에 백업하며, 클라이언트별로 설정 수정 도중 실패하면 이미 수정한 설정 파일을 이 백업에서 자동으로 되돌림.
7. ③에서 `backup_sync_*` 폴더를 영구 삭제함.
8. 링크 해제로 UHD/HD/SD 폴더가 비게 되면 해당 번들을 `launcherDownloadConfig.json`에서 제거하고, 다른 번들이 쓰지 않는 팩 파일(`common.json`은 제외)을 삭제함. 설정 정리에 실패하면 경고창으로 알림.
9. 클라이언트 종류 자동 판정: 먼저 런처 폴더의 `<런처 버전>\Assets\KRApp.conf`(버전이 높은 폴더부터 차례로 시도해 읽을 수 있는 첫 파일을 씀, Base64 인코딩 후 각 바이트를 XOR 0x63한 JSON)에서 앱ID(공식 50004, 구글 50009, 에픽 50003, 스팀 50019)를 읽음. 런처만 설치하고 게임을 받기 전에도 있는 파일임. 이 파일은 읽기만 하며 내용은 로그에 남기지 않음. 파일이 없으면 `%AppData%\Roaming\KRLauncher\C<앱ID>\log`의 로그(각 바이트가 XOR 0x09로 인코딩됨)에서 설치 경로를 찾음. 기본 로그 최신 30개의 앞 256 KB만 읽으며, 가장 많이 일치한 종류를 선택하고 동률이거나 없으면 미지정으로 둠. 게임 폴더 설정 JSON의 앱ID는 에픽과 스팀이 같아서 쓰지 않음.
10. 클라이언트 이식 설정: 대상에 `launcher.exe`만 있고 `Wuthering Waves Game` 폴더가 비어 있으면 원본 `launcherDownloadConfig.json`의 버전과 선택한 품질 번들(`UHD`/`HD`/`SD`), 팩 파일(`launcherDownloadConfig\*.json`)을 바탕으로 대상에 같은 이름의 설정 파일을 새로 만들고 앱 ID는 선택한 런처 종류로 설정함. 대상에 이미 설정 파일이 있으면 만들지 않음. `원본 DB 복사`를 켜 두면 원본의 `Client\Saved\LocalStorage\LocalStorage.db` 한 개를 대상의 같은 위치에 복사함(대상에 이미 있으면 건드리지 않음). 게임은 시작할 때 이 파일의 완료 임무 목록을 보고 지난 임무의 영상을 받지 않으므로, 이 파일이 없는 새 클라이언트는 첫 실행 때 영상 리소스를 모두 받음. 만든 파일과 링크를 만들 때 생긴 빈 폴더는 되돌리기로 삭제할 수 있고, 완료 전에는 설정 파일의 앱 ID만 바꿔 종류를 변경할 수 있음. 이후 링크 생성과 대상 런처의 [게임 복구] 순서로 진행함.

## 판정 기준

| 항목 | 기준 |
|---|---|
| 클라이언트 구성 | 런처 `launcher.exe`와 `Wuthering Waves Game\Wuthering Waves.exe`가 있어야 함 |
| 버전 | `launcherDownloadConfig.json`의 `bundles.*.version` 중 최대값 |
| 링크 가능 | 앞 두 자리(Major.Minor)가 같음. 끝자리만 다르면 `패치 버전이 다르므로 업데이트 권장` 안내 |
| 이식 가능 / 부분 복구 필요 | 런처만 있고 클라이언트가 없는 대상. 설치 폴더가 비어 있으면 `이식 가능`, 파일이 일부 남아 있으면 `부분 복구 필요`(원본으로 선택 불가, 런처 [게임 복구]로 마저 받은 뒤 사용). 링크 관리 탐색에서는 같은 조건이 각각 `이식 필요`, `부분 복구 필요`로 표시되며 보라색 배지로 등록할 수 있음 |
| 링크 탐색의 `링크 구성됨` / `일부 링크됨` | 원본 기준으로 대상의 링크 현황을 봄. 필수 폴더(`Paks`, `Resources`)가 모두 링크돼 있고 품질 리소스(UHD/HD/SD)가 원본에 있는 것 중 하나 이상 링크돼 있으면 `링크 구성됨`(어느 품질인지는 상관없음). 일부만 링크돼 있으면 `일부 링크됨`이며 남은 폴더를 설명 줄에 표시함 |
| 링크 관리 탐색의 `업데이트 필요` / `링크 불가` | 등록된 원본과 앞 두 자리가 다른 클라이언트. 대상이 더 낮으면 `업데이트 필요`, 더 높으면 `링크 불가`(원본을 먼저 업데이트해야 함). 체크할 수는 있으며, 체크할 때와 직접 경로로 등록할 때 확인 팝업을 한 번 더 띄움. 낮은 쪽은 런처 업데이트를 먼저 권장하고, 강제로 등록하면 등록 직후 `링크 연결 후 업데이트 순서 안내` 창이 `업데이트` 배지용 순서(`업데이트` 배지 의미 → [링크 연결]로 원본과 링크 구성 → `동기화 필요`로 바뀜 → [업데이트 후 동기화] 진행)로 자동으로 뜸. 낮은 버전을 연결하면 링크가 끝난 뒤 '런처를 실행하지 말고 [업데이트 후 동기화]를 먼저 진행하라'는 안내창이 뜨고, 런처 실행 여부는 묻지 않음 |
| 링크 관리 탐색의 `원본 후보` | 등록된 원본이 없을 때 탐색 결과에서 추정함. 다른 클라이언트가 가장 많이 링크한 폴더가 우선이고, 없으면 폴더가 모두 실제 폴더인 클라이언트(일부만 링크된 클라이언트는 제외) 중 용량이 가장 큰 것. 버전은 비교하지 않음 |
| 배지 `동기화` / `동기화 필요` | 원본에 링크됨. 앞 두 자리가 같으면 `동기화`, 다르면 `동기화 필요` |
| 배지 `최신` / `업데이트` / `링크 불가` | 링크 없음. 앞 두 자리가 같으면 `최신`, 원본보다 낮으면 `업데이트`, 원본보다 높으면 `링크 불가`. `링크 불가`는 연결 칸을 선택할 수 없고, 칸이나 열 머리를 누르면 `등록된 원본보다 더 높은 버전입니다. 원본을 업데이트해야 합니다.`로 안내함 |
| 배지 `미확인` | 클라이언트가 없거나 버전을 읽지 못함. 탐색 창에서는 클라이언트 파일은 있는데 `launcherDownloadConfig.json`에서 버전을 읽지 못한 경우에 표시하고 선택할 수 없음 |
| 중단 조건 | 런처, 게임 실행 중 / 원본이 링크이거나 폴더가 없음 / 원본과 대상이 같거나 포함 관계 / 대상의 앞 두 자리 버전이 원본과 다름(링크 관리에서는 대상이 원본보다 낮은 경우 허용하고, 링크 후 `동기화 필요`로 안내) / 원본 또는 대상의 버전을 읽을 수 없음 / 심볼릭 링크 권한 없음 |

## 사용 시점과 주의할 점

- 원본 클라이언트를 삭제하거나 이동하면 링크가 모두 깨짐.
- 연결된 폴더는 모든 클라이언트에서 공유되므로 임의로 수정하거나 지우지 말 것.
- 링크 해제는 도구의 [링크 해제]나 `cmd /c rmdir`로 하고, PowerShell 5.1의 `Remove-Item -Recurse`는 링크 대상까지 지울 수 있으니 쓰지 말 것.
- 인게임 [리소스 정리]는 한 곳에서만 해도 모두 반영되며, `로그인 시 자동 제거 허용`은 끄는 것을 권장함.
- 클라이언트 종류 자동 판정이 안 되면(런처 설정 파일과 로그가 모두 없음) 미지정으로 두고 직접 선택하면 됨. 이식 설정에서 런처 설정과 다른 종류를 고르면 경고함.
- `원본 DB 복사`는 그래픽·소리·조작 설정과 최근 로그인 기록도 함께 복사함. 원본과 다른 계정을 쓰는 경우에는 끄는 것을 권장함. 끄고 이식했다면 첫 실행 때 지난 임무 영상(약 29 GB)을 받으며, 로그인 후 게임 설정의 [리소스 정리]로 지울 수 있음.
- 새 버전의 폴더 구조가 바뀌면 동작이 달라질 수 있음. 동기화 전에 문제가 감지되면 아무것도 바꾸지 않고 사유를 보여 줌.

## 면책 조항

- 이 도구는 개인이 만든 비공식 도구이며, 쿠로게임즈 및 명조(Wuthering Waves)와 관련이 없음. 게임 이름과 상표는 각 소유자의 것임.
- 클라이언트 폴더의 이름 변경, 심볼릭 링크 생성, 런처 설정 JSON 생성·수정, DB 파일(`LocalStorage.db`) 복사(이식 설정에서 선택 시), 사전 다운로드 파일 이동, 백업 폴더 영구 삭제를 수행함. 링크 해제 후 폴더가 비면 품질 번들과 전용 팩 설정 파일도 삭제함. 런처 로그는 읽기만 하며, 게임 서버나 계정 정보, 게임 실행 파일 자체는 수정하지 않음.
- 관리자 권한으로 동작하므로, 실행 전에 스크립트 내용을 직접 확인할 것을 권장함.
- 이 도구의 사용으로 생기는 데이터 손실, 게임 문제, 계정 관련 불이익 등 어떠한 결과에 대해서도 작성자는 책임지지 않음. 사용에 따른 책임은 사용자에게 있음.
