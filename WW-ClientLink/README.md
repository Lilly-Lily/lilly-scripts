# 명조 클라이언트 심볼릭 링크 도구 (WW-ClientLink)

명조(Wuthering Waves) 클라이언트 여러 개가 대용량 리소스 폴더를 공유하도록 심볼릭 링크로 연결해 주는 GUI 도구임. v1.0

공식(쿠로), 구글, 에픽, 스팀 등 클라이언트를 따로 설치하면 각각 100 GB 안팎을 차지함. 원본 한 곳에 실제 파일을 두고 나머지 클라이언트의 `Paks`, `UHD`, `Saved\Resources` 폴더를 원본으로 연결하면, 클라이언트마다 고유 파일(약 5 GB)만 남아 용량이 크게 줄어듦. 링크 생성뿐 아니라 업데이트 후 링크 클라이언트의 설정을 맞추는 [업데이트 후 동기화]까지 지원함.

> [!WARNING]
> 폴더를 실제로 이름 변경, 링크, 삭제하는 도구임. 사용 전 [면책 조항](#면책-조항)을 꼭 읽을 것.

## 다운로드

[Release 페이지](https://github.com/Lilly-Lily/lilly-scripts/releases?q=WW-ClientLink)에서 가장 최신 버전의 `WW-ClientLink-v버전.zip`(예: `WW-ClientLink-v1.0.zip`) 파일을 받을 수 있음. `Source code`는 저장소 전체 사본이므로 받지 말 것.

## 주요 기능

- **링크 생성**: 원본 클라이언트의 `Paks`, `Saved\Resources`(영상 포함), UHD/HD/SD 폴더를 대상 클라이언트에 심볼릭 링크로 연결함. [링크 실행]을 누르면 변경 내용을 팝업으로 확인한 뒤 진행하며, 대상의 기존 폴더는 삭제하지 않고 `_backup`을 붙여 보관함. 이후 대상 런처에서 [게임 복구]와 게임 실행을 확인하고, 확인 단계를 거쳐 [백업 삭제]로 정리함. 필요하면 [되돌리기]로 취소하며, 완료 후 링크 관리 목록에 등록할 수 있음.
- **링크 관리**: 클라이언트(원본 1 + 링크 3, 최대 4개)를 등록해 링크 현황 표로 확인하고, 연결, 해제, 깨진 링크 정리, 백업 삭제를 함. 흔한 위치, Steam 라이브러리, 저장소 전체 탐색(탐색 정확도: 빠름/보통/정확)으로 클라이언트를 찾을 수 있음.
- **업데이트 후 동기화**: 원본을 업데이트한 뒤 링크 클라이언트의 설정 JSON 버전을 맞추고 사전 다운로드 파일을 안전하게 치워, 링크 런처에서 [게임 복구]만으로 끝나게 함.
- **동기화 안내**: 동기화가 필요한 클라이언트에 `(동기화 필요)` 배지와 붉은 배경이 표시되고, [동기화 순서 안내] 팝업이 순서를 알려 줌.
- **버전 검사**: 원본과 대상의 앞 두 자리 버전이 다르면 링크를 막고, 끝자리만 다르면 경고함.

## 요구 사항

- Windows 10 이상, Windows PowerShell 5.1
- 심볼릭 링크 생성을 위해 관리자 권한 또는 Windows 개발자 모드 필요
- 원본과 대상 클라이언트가 모두 같은 PC의 로컬 드라이브에 있어야 함

## 사용법

1. [다운로드](#다운로드)한 zip의 압축을 풀고, `WW-ClientLink.ps1`과 `WW-ClientLink.bat` 우클릭 > 속성 > 하단 `차단 해제`를 체크함.
2. `WW-ClientLink.bat`을 우클릭 > `관리자 권한으로 실행`함. (Windows 개발자 모드가 켜져 있으면 더블클릭으로 충분함. PowerShell에서 직접 실행하려면 관리자 PowerShell에서 `powershell -NoProfile -ExecutionPolicy Bypass -File .\WW-ClientLink.ps1`)
3. 모든 명조 런처와 게임을 종료함.
4. [링크 관리] 탭에서 `＋ 클라이언트 추가`로 원본과 링크 클라이언트를 등록함.
5. 연결할 칸을 선택하고 [선택 항목 연결]을 누름. 이후 링크 클라이언트의 런처에서 실행과 [게임 복구]를 확인하고, 이상 없으면 [백업 삭제]로 정리함.

### 업데이트할 때

1. 원본 클라이언트만 일반 업데이트(사전 다운로드 포함)를 완료함. 링크 쪽 런처에서는 업데이트를 누르지 말 것.
2. 모든 런처와 게임을 종료하고, 도구의 [링크 관리] 탭에서 `(동기화 필요)` 배지를 확인함.
3. [업데이트 후 동기화]를 열고 ①을 실행함.
4. 링크 클라이언트마다 런처에서 일반 업데이트가 아닌 [게임 복구]를 하고, 클라이언트를 실행해 잔여 파일을 자동 업데이트함.
5. 모든 클라이언트의 실행이 확인되면 ②, ③으로 보관한 설정과 사전 다운로드 백업을 영구 삭제함.

| `WW-ClientLink.ps1` | 도구 본체 |
| `WW-ClientLink.bat` | 본체를 콘솔 창 없이 실행하는 실행 파일 |
| `README.md` | 설명서 |
| `LICENSE` | MIT 라이선스 |
| `.gitignore`, `.gitattributes` | 저장소 설정 |

실행 중 도구 폴더에 `WW-ClientLink.json`(등록 정보)과 `logs`(로그)가 자동 생성되며 저장소에는 포함하지 않음.

## 동작 원리

1. 링크는 복사가 아니라 같은 폴더를 두 경로로 접근하게 만드는 것임. 어느 클라이언트에서 수정, 삭제해도 모두에 반영됨.
2. 링크 생성: 대상 폴더를 `_backup`으로 이름 변경 → 같은 자리에 심볼릭 링크 생성 → 경로 확인 → 실패하면 백업 복원.
3. 링크 클라이언트 런처로 업데이트(사전 다운로드 포함)하면 링크 너머 원본 파일이 패치 재료로 옮겨져 원본이 손상됨. 그래서 업데이트는 원본에서만 하고, 링크 쪽은 설정 JSON의 버전을 맞춘 뒤 [게임 복구]를 사용함.
4. [업데이트 후 동기화] ①: 링크 클라이언트의 `launcherDownloadConfig.json`, `common.json`, `uhd.json`의 버전 필드를 원본 버전으로, `launcherDownload` 쪽 사전 다운로드 플래그를 `false`로 수정함. 파일 전체가 아닌 필드만 고치며, 임시 파일에 쓰고 검증한 뒤 교체함.
5. 사전 다운로드 파일(`launcherDownload` 합계 1 GB 이상일 때 감지, 100 MB 이상인 버전 폴더)은 `<Game>\backup_sync_<시각>\predownload`로 옮김. 중간에 실패하면 옮긴 파일을 되돌림. 수정 전 설정은 `backup_sync_<시각>\settings`에 백업함.
6. ③에서 `backup_sync_*` 폴더를 영구 삭제함.

## 판정 기준

| 항목 | 기준 |
|---|---|
| 클라이언트 구성 | 런처 `launcher.exe`와 `Wuthering Waves Game\Wuthering Waves.exe`가 있어야 함 |
| 버전 | `launcherDownloadConfig.json`의 `bundles.*.version` 중 최대값 |
| 링크 가능 | 앞 두 자리(Major.Minor)가 같음. 끝자리만 다르면 경고 |
| 동기화 필요 | 원본과 앞 두 자리가 다름. 버전을 못 읽으면 알 수 없음 |
| 중단 조건 | 런처, 게임 실행 중 / 원본이 링크이거나 폴더가 없음 / 원본과 대상이 같거나 포함 관계 / 심볼릭 링크 권한 없음 |

## 사용 시점과 주의할 점

- 원본 클라이언트를 삭제하거나 이동하면 링크가 모두 깨짐.
- 연결된 폴더는 모든 클라이언트에서 공유되므로 임의로 수정하거나 지우지 말 것.
- 링크 해제는 도구의 [선택 항목 해제]나 `cmd /c rmdir`로 하고, PowerShell 5.1의 `Remove-Item -Recurse`는 링크 대상까지 지울 수 있으니 쓰지 말 것.
- 인게임 [리소스 정리]는 한 곳에서만 해도 모두 반영되며, `로그인 시 자동 제거 허용`은 끄는 것을 권장함.
- 새 버전의 폴더 구조가 바뀌면 동작이 달라질 수 있음. 동기화 전에 문제가 감지되면 아무것도 바꾸지 않고 사유를 보여 줌.

## 면책 조항

- 이 도구는 개인이 만든 비공식 도구이며, 쿠로게임즈 및 명조(Wuthering Waves)와 관련이 없음. 게임 이름과 상표는 각 소유자의 것임.
- 클라이언트 폴더의 이름 변경, 심볼릭 링크 생성, 설정 JSON 수정, 사전 다운로드 파일 이동, 백업 폴더 영구 삭제를 수행함. 게임 서버나 계정 정보, 게임 실행 파일 자체는 수정하지 않음.
- 실행 전에 스크립트 내용을 직접 확인할 것을 권장함.
- 이 도구의 사용으로 생기는 데이터 손실, 게임 문제, 계정 관련 불이익 등 어떠한 결과에 대해서도 작성자는 책임지지 않음. 사용에 따른 책임은 사용자에게 있음.
