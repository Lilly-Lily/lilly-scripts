# 키 입력 추적기 (Key Input Tracer)

키보드 입력이 실제 키보드에서 온 것인지, 다른 프로그램이 끼워 넣은(주입한) 것인지 구분해서 기록하는 도구임.

입력할 때마다 키 이름, 입력 구분, 그때 활성화된 창의 프로세스를 함께 남김. 한글 입력 중 영문이 섞이는 등 원치 않는 키가 들어올 때 원인이 키보드인지, 다른 프로그램인지 가려내는 데 씀.

> [!WARNING]
> 모든 키 입력을 기록하는 도구이므로 추적 중에 입력한 비밀번호도 로그에 남음. 사용 전에 [면책 조항](#면책-조항)을 확인할 것.

## 주요 기능

- 실제 키 / 주입된 키 구분 표시 (주입된 키는 빨간 줄)
- 키를 누른 순간의 활성 창 프로세스 기록
- 문제가 생긴 시점을 표시하는 [증상 표시] 버튼
- 주입된 키만 걸러 보기
- CSV 로그 저장, 실시간 자동 저장
- 창 항상 위 고정

## 요구 사항

- Windows 10 / 11
- Windows PowerShell 5.1 (Windows 기본 포함)
- 관리자 권한 필요 없음

## 사용법

1. `key-input-tracer.bat`과 `key-input-tracer.ps1`을 같은 폴더에 둠.
2. 인터넷에서 받은 파일이라 실행이 막히면 `key-input-tracer.ps1` 우클릭 → 속성 → **차단 해제** 체크 → 확인.
3. `key-input-tracer.bat`을 더블클릭함. 창이 뜨면 바로 추적이 시작됨.
4. 오래 지켜볼 때는 [자동 저장]을 켜고 창을 최소화한 채 평소처럼 사용함.
5. 증상이 나오면 바로 [증상 표시]를 누르고, 그 주변 줄을 확인함.

## 구성 파일

| 파일 | 역할 |
| --- | --- |
| `key-input-tracer.bat` | 실행 정책을 우회(`-ExecutionPolicy Bypass`)하고, 콘솔 창을 숨긴 채 `.ps1`을 실행하는 런처 |
| `key-input-tracer.ps1` | 창(UI), 키보드 훅, 로그 표시·저장을 모두 담당하는 본체 |
| `keylog_auto_날짜_시각.csv` | [자동 저장]을 켜면 `.ps1`과 같은 폴더에 생기는 실시간 로그 |

로그 파일(`keylog_*.csv`, `keylog_*.txt`)은 실행 중 자동 생성되며 입력 내용이 담기므로 저장소에 포함하지 않음.

## 동작 원리

1. Windows의 저수준 키보드 훅(`WH_KEYBOARD_LL`)을 설치해 모든 키 누름을 받아 봄.
2. 키를 가로채거나 막지 않고 그대로 다음 프로그램에 넘기므로 평소 입력에는 영향이 없음.
3. Windows는 프로그램이 `SendInput` 등으로 만든 키에 '주입됨(injected)' 표시를 붙여 넘겨줌. 이 표시로 실제 입력과 주입된 입력을 구분함.
4. 키를 누를 때(`KeyDown`, `SysKeyDown`)만 기록하고, 뗄 때는 기록하지 않음.
5. 기록은 0.15초마다 새 입력이 있을 때만 화면에 반영함.

## 화면 구성

| 열 | 의미 |
| --- | --- |
| 시각 | 키를 누른 시각(밀리초까지) |
| 키 | 키 이름. 한/영 키는 `HanYeong`, 한자 키는 `Hanja`로 표시 |
| Scan | 하드웨어 스캔 코드. 실제 키보드 입력이면 키마다 정해진 값이 나옴 |
| 구분 | 실제 키 / [주입됨] |
| Extra | 입력을 만든 쪽이 붙인 부가 정보. 주입된 키라면 0이 아닌 값이 특정 프로그램의 흔적일 수 있음 |
| 입력 창(프로세스) | 키를 누를 때 활성화돼 있던 창의 프로세스 이름 |

| 줄 색 | 의미 |
| --- | --- |
| 흰색 | 실제 키보드 입력 |
| 분홍색(빨간 글씨) | 프로그램이 주입한 입력 |
| 노란색 | [증상 표시]로 남긴 표시 줄 |

| 버튼·옵션 | 동작 |
| --- | --- |
| 추적 중지 / 추적 시작 | 키보드 훅을 끄거나 켬. 중지해도 지금까지의 기록은 남음 |
| 증상 표시 | 지금 시각에 노란 표시 줄을 넣음 |
| 로그 저장... | 지금까지의 전체 기록을 CSV 또는 TXT로 저장. 기본 파일명은 `keylog_날짜_시각.csv` |
| 지우기 | 화면과 메모리의 기록, 건수를 모두 비움. 자동 저장 파일은 지우지 않음 |
| 주입된 키만 보기 | 주입된 키와 표시 줄만 목록에 보여줌. 기록 자체는 계속 전부 남음 |
| 자동 저장 | 켜는 순간 새 CSV 파일을 만들고, 이후 입력을 실시간으로 덧붙임 |
| 항상 위 | 추적기 창을 다른 창보다 항상 위에 둠 |

화면 목록은 최근 5,000줄까지만 보여줌. 저장할 때는 지우기 전까지의 전체 기록이 들어감.

로그 파일은 CSV(UTF-8 BOM)라서 엑셀에서 바로 열림. 열은 `Time, Key, Scan, Type, Extra, Window` 순서이고, `Type`은 `real` / `INJECTED` / `MARK` 중 하나임.

## 결과 해석

| 현상 | 의미 | 다음 단계 |
| --- | --- | --- |
| 문제의 키가 [주입됨]으로 찍힘 | 다른 프로그램이 키를 만들어 넣음 | Extra 값과 시각을 참고해 상주 프로그램을 하나씩 꺼 보며 범인을 찾음 |
| 문제의 키가 실제 키로 찍힘 | 키보드에서 실제로 눌린 입력 | 키보드 작동점·캘리브레이션 등 하드웨어 설정을 확인 |
| 키는 정상인데 글자만 영문으로 나옴 | 키 입력이 아니라 입력기(IME)의 한/영 상태가 바뀐 것 | 입력기를 건드리는 프로그램을 확인. 이 도구는 IME 상태 변화를 기록하지 않음 |
| 훅 설치 실패 경고가 뜸 | 키보드 보안 프로그램이 훅을 막고 있을 수 있음 | 보안 프로그램을 잠시 끄고 다시 실행 |

## 사용 시점과 주의할 점

- 원인을 찾는 동안만 켜 두고, 찾은 뒤에는 끄고 로그 파일을 지울 것.
- 자동 저장을 켜 두면 파일이 계속 커짐. 오래 켜 둘 때는 가끔 정리할 것.
- 다른 프로그램이 이미 키보드 훅을 쓰고 있으면, 추적기를 켜는 것만으로 훅 처리 순서가 바뀌어 증상이 잠시 사라질 수 있음. 최소화해 두고 평소처럼 쓰다가 증상이 다시 나올 때 확인하는 것이 좋음.
- 경로의 `\`가 `₩`로 보이는 것은 한글 글꼴의 표시 방식이며 실제 경로에는 문제없음.
- `.ps1`을 메모장으로 수정할 때는 인코딩을 'UTF-8(BOM)'으로 유지할 것. BOM이 없으면 한글이 깨져서 실행되지 않음.

## 면책 조항

- 이 도구는 개인이 만든 비공식 도구이며, 특정 게임사나 프로그램 제작사와 관련이 없음. 언급된 프로그램 이름과 상표는 각 소유자의 것임.
- 키 입력을 읽기만 하고 막거나 바꾸지 않음. 파일은 사용자가 저장하거나 자동 저장을 켰을 때만 만들고, 인터넷으로 아무것도 보내지 않음.
- 모든 키 입력을 기록하므로 비밀번호 등 민감한 입력이 로그에 남을 수 있음. 로그 파일 관리는 사용자의 책임임.
- 본인 PC의 문제를 진단하는 용도로만 사용할 것. 다른 사람의 PC에서 동의 없이 사용하면 안 됨.
- 이 도구의 사용으로 생기는 데이터 손실, 정보 유출, 프로그램 문제 등 어떠한 결과에 대해서도 작성자는 책임지지 않음. 사용에 따른 책임은 사용자에게 있음.
